⚖️ Gold Weight Converter

A clean, open-source Flutter application to convert gold weight between traditional South Asian units (Tola, Masha, Ana, Ratti) and metric grams, with a built-in real-time gold price estimator.

Flutter 3.x Dart ^3.7.2 Riverpod 3.3.1 Version 1.2.0+2 Open Source Android · iOS · Web · Desktop

1. Project Overview

The Gold Weight Converter is a Flutter mobile (and multi-platform) application that solves a practical problem for gold traders, jewellers, and consumers in South Asia: traditional gold measurement units — Tola, Masha, Ana, Ratti — coexist with the metric system (grams), and converting between them by hand is error-prone.

The app lets users enter any combination of the five units, instantly see the full weight breakdown in every unit, and optionally calculate the monetary value of that gold based on a live or manually entered market rate (per Tola, per 10 g, or per gram).

Target Audience

  • Gold traders and jewellers in Pakistan, India, Bangladesh, and the wider South Asian diaspora
  • Customers buying or selling gold jewellery who need a quick weight/price check
  • General users curious about traditional weight-unit equivalencies

2. Features

  • 🔁 Bi-directional conversion — enter any unit(s); all others calculate automatically
  • 💰 Gold price calculator — enter a rate per Tola, per 10 g, or per 1 g to get the total value in Pakistani Rupees
  • 📊 Detailed result breakdown — shows the calculation steps, not just the final answer
  • 🎯 Real-time calculation — results update as you type (no need to press Calculate)
  • 🧼 One-tap reset — Clear All button wipes all inputs and results
  • 🧮 Smart number formatting — input fields auto-format with thousand separators
  • ♿ Accessibility — all interactive elements have semantic labels; results are selectable text
  • 🌍 Localization-ready — ARB file and l10n.yaml configured for future multi-language support

7. Modules & File Descriptions

📄 lib/main.dart

Role: Application entry point and theme configuration.

main() calls runApp(MyApp()). MyApp is a StatelessWidget that wraps the entire widget tree in ProviderScope (required by Riverpod) and configures a MaterialApp with:

  • An amber/gold ColorScheme derived from Colors.amber
  • Global AppBarTheme (amber gradient background, white text)
  • Global ElevatedButtonThemeData (amber, rounded corners)
  • Global InputDecorationTheme (rounded borders, amber focus ring)
  • debugShowCheckedModeBanner: false

The single home is GoldConverterScreen().

📄 lib/converter_screen.dart

Role: The single screen of the app. Extends ConsumerStatefulWidget so it can both hold mutable controller state and read/write Riverpod providers.

Controllers managed

  • tolaController, mashaController, anaController, rattiController, gramController — weight input fields
  • goldRateController — market rate input
  • scrollController — auto-scrolls to results after Calculate is pressed

Key methods

  • _calculate() — core conversion logic; called on every keystroke
  • calculateAll() — unfocuses keyboard, calls _calculate(), then animates scroll to results
  • _clearAll() — clears all controllers and resets provider state
  • _getDouble(controller) — safely parses a formatted text field value
  • _validateInput(value) — returns an error string for invalid/negative input

UI structure (build method)

  • Gradient AppBar with amber-to-deep-amber gradient
  • Gradient scaffold body (SingleChildScrollView)
  • Six GoldTextField widgets (Tola, Masha, Ana, Ratti, Gram, Gold Rate)
  • Gold Rate field uses the hasDropdown: true variant with a UnitEnum selector
  • Calculate + Clear All button row
  • Two lazy Consumer widgets for results (weights section + price section)

unit_enum.dart

Defines UnitEnum, an enhanced Dart enum with a human-readable name string field. This avoids stringly-typed comparisons throughout the codebase. 

enum UnitEnum {
  tola('Tola'),
  tenGram('10 Gram'),
  oneGram('1 Gram');

  final String name;
  const UnitEnum(this.name);

  static UnitEnum fromString(String? value) { ... }
}

fromString() safely converts a dropdown string back to an enum value, defaulting to UnitEnum.tola if no match is found (safe fallback).

📁 lib/models/

gold_result_model.dart

A simple immutable data class holding the two displayable result strings. Both fields are nullable — null means "not yet calculated / cleared". 

class GoldResultModel {
  final String? weightsText;  // Multi-line conversion breakdown
  final String? priceText;    // Formatted price string or null

  GoldResultModel({this.weightsText, this.priceText});

  GoldResultModel copyWith({String? weightsText, String? priceText}) { ... }
}

The copyWith() method enables immutable state updates inside GoldResultNotifier without replacing the entire object unnecessarily.

📁 lib/providers/

unit_provider.dart — rateUnitProvider

A StateProvider<UnitEnum> that tracks which pricing unit the user has selected in the Gold Rate dropdown. Default is UnitEnum.tola.

StateProvider is appropriate here because the state is a single primitive value with no derived logic — it is written directly via ref.read(rateUnitProvider.notifier).state = newUnit.

The file also contains commented-out alternative implementations (NotifierProvider and the legacy StateNotifierProvider) that serve as educational reference for the developer.

weight_provider.dart — goldResultNotifierProvider

A NotifierProvider<GoldResultNotifier, GoldResultModel>. The GoldResultNotifier class manages three state mutations:

  • setGoldWeights(String? weights) — updates the conversion breakdown text
  • setGoldPrice(String? price) — updates the price text
  • clearResults() — resets to a fresh GoldResultModel()

Consumers use .select() to subscribe to individual fields, avoiding unnecessary rebuilds when only one of the two fields changes. 

// Example selective watch in the UI:
ref.watch(goldResultNotifierProvider.select(
  (model) => model.weightsText,
));
📁 lib/utils/

number_formatter.dart — ThousandsSeparatorInputFormatter

Implements TextInputFormatter (Flutter's interface for intercepting and transforming text field input). Applied to every numeric input field in the app.

Key responsibilities:

  • Strip all non-digit and non-decimal characters
  • Ensure only one decimal point is present
  • Re-format the integer part with #,##0 thousand separators using intl
  • Preserve trailing decimal points while the user is mid-typing (e.g. "1,234.")
  • Accurately recalculate cursor position accounting for added/removed commas

number_helper.dart — NumberHelper

8. Conversion Logic

Unit Conversion Constants

UnitGramsSub-units
1 Tola11.66 g= 12 Masha = 16 Ana = 96 Ratti
1 Masha0.972 g= 1.333 Ana = 8 Ratti
1 Ana0.72875 g= 6 Ratti
1 Ratti0.1215 g—

Weight Aggregation Formula

The gram is used as the universal intermediate unit. All entered units are converted to grams and summed: 

totalGrams = (tola  × 11.66)
           + (masha × 0.972)
           + (ana   × 0.72875)
           + (ratti × 0.1215)
           + gram

Then the total is converted back to every unit:

tolaResult  = totalGrams / 11.66
mashaResult = totalGrams / 0.972
anaResult   = totalGrams / 0.72875
rattiResult = totalGrams / 0.1215

Gold Price Formula

The user enters a rate and selects which unit the rate applies to. The rate is normalised to grams first, then multiplied by the total weight: 

// If rate is per Tola:
gramRate = rate / 11.66

// If rate is per 10 Gram:
gramRate = rate / 10

// If rate is per 1 Gram:
gramRate = rate

// Final price:
price = totalGrams × gramRate

The price is formatted using NumberFormat.currency(locale: 'en_PK', symbol: 'Rs. ', decimalDigits: 2), producing output like Rs. 1,50,000.00.

9. Key Functions

_calculate() — converter_screen.dart

Called by: every GoldTextField.onChanged callback and by calculateAll()

Does not unfocus the keyboard (to avoid disrupting the user while typing).

  1. Reads all 6 controllers via _getDouble()
  2. If all weight values are zero → calls clearResults() and returns early
  3. Aggregates inputs to totalGrams and builds a human-readable StringBuffer
  4. Reads rateUnitProvider, normalises rate to per-gram, computes price
  5. Compares new strings to existing state — only calls notifier if changed (avoids needless rebuilds)

calculateAll() — converter_screen.dart

Called by: the Calculate button

  1. Calls FocusScope.of(context).unfocus() to dismiss the keyboard
  2. Calls _calculate()
  3. After the current frame renders (addPostFrameCallback), animates the scroll controller to the bottom so the results are visible

_clearAll() — converter_screen.dart

  1. Unfocuses any active text field
  2. Calls .clear() on all 6 controllers
  3. Calls goldResultNotifierProvider.notifier.clearResults() to reset provider state to GoldResultModel()

_getDouble(TextEditingController) — converter_screen.dart

Safe parser: trims whitespace, returns 0.0 for empty/invalid/negative values by delegating to NumberHelper.parseFormattedNumber().

ThousandsSeparatorInputFormatter.formatEditUpdate() — utils/number_formatter.dart

  1. Returns the value unchanged if empty
  2. Strips all characters except digits and .
  3. Collapses multiple . into one
  4. If the cleaned string ends with ., formats the integer part only and re-appends .
  5. Otherwise, formats the full number via AppConstants.thousandNumberFormat
  6. Recalculates cursor position by counting comma deltas between old and new text

NumberHelper.parseFormattedNumber(String) — utils/number_helper.dart

Strips commas via cleanNumber(), then calls double.tryParse(). Returns null for invalid input — never throws.

10. Design Patterns & Best Practices

Reactive State Management (Riverpod)

State is owned by Riverpod providers, not by setState. The UI never mutates state directly — it calls notifier methods. This makes state changes predictable and testable independently of the widget tree.

The commented-out setState blocks left in converter_screen.dart show the migration history from setState to Riverpod and serve as a useful learning reference.

Selective Rebuilds with .select()

The two result sections use ref.watch(provider.select(...)) to subscribe only to the specific field they display. This means updating priceText does not rebuild the weights section and vice versa — an important performance optimisation for forms with many fields.

Immutable State with copyWith()

GoldResultModel is immutable. The notifier always produces a new model via copyWith() rather than mutating fields in place. This enables Riverpod's equality-based rebuild optimisation.

Composition over Inheritance

GoldTextField is a composable widget that accepts a hasDropdown flag to switch between two internal layouts. Rather than having separate GoldTextFieldWithDropdown and GoldTextField classes, a single widget handles both cases via conditional branching — keeping the parent screen simple.

Accessibility (Semantics)

Every interactive element is wrapped in a Semantics widget with a label (and button: true for buttons). This ensures screen readers (TalkBack on Android, VoiceOver on iOS) can describe each element to users with visual impairments.

Results use SelectableText instead of plain Text, allowing users to copy conversion details or prices to the clipboard.

Input Safety

All raw text field values are sanitised through NumberHelper.parseFormattedNumber() before any arithmetic is performed. Negative values and non-parseable strings return 0.0 via _getDouble(), preventing crashes or nonsensical results.

Defensive Enum Parsing

UnitEnum.fromString() uses firstWhere with an orElse fallback (UnitEnum.tola) instead of throwing an exception. This prevents the app from crashing if a dropdown sends an unexpected string value.

Post-Frame Scroll

After calculating, the app calls WidgetsBinding.instance.addPostFrameCallback() to defer the scroll animation until after the result widgets have been built and laid out. Without this, scrollController.position.maxScrollExtent would return a stale value.

13. Localization

The app uses Flutter's official flutter_localizations + ARB-based localization system, configured via l10n.yaml: 

# l10n.yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart

How to add a new language

  1. Copy lib/l10n/app_en.arb to lib/l10n/app_ur.arb (for Urdu)
  2. Translate all string values (keep the keys identical)
  3. Run flutter gen-l10n — this generates app_localizations_ur.dart
  4. Add the locale to MaterialApp.supportedLocales in main.dart
  5. Replace hardcoded strings in converter_screen.dart with AppLocalizations.of(context).fieldName
Current Status The ARB file covers 100% of the UI strings. The generated AppLocalizations class is available but not yet consumed by the UI. Wiring it in is a small, well-scoped task — every hardcoded string in converter_screen.dart has a corresponding ARB key ready to use.

14. Assumptions & Notes

Assumption 1 — Localization not yet wired to UI The app_en.arb file and generated AppLocalizations class are fully configured, but all strings in converter_screen.dart are currently hardcoded in English. The localization system is infrastructure-ready for adding more languages in the future.
Assumption 2 — Duplicate conversion constants The four conversion ratios are defined in both AppConstants and as inline static const values inside _GoldConverterScreenState. The inline copies are the ones actually used in _calculate(). The AppConstants values are used only by NumberHelper and ThousandsSeparatorInputFormatter (for the NumberFormat). A future cleanup should remove the inline copies from converter_screen.dart and use AppConstants everywhere.
Note — Calculation logic in the View layer The _calculate() method lives in _GoldConverterScreenState (the View) rather than in a Notifier (the ViewModel). This works correctly and keeps the code simple for a single-screen app, but it means the calculation logic is coupled to the widget lifecycle and cannot easily be unit-tested in isolation. A future refactor could move this logic into GoldResultNotifier.
Note — Currency locale The price is formatted with locale: 'en_PK' and symbol: 'Rs. '. This assumes the primary user base is in Pakistan. For a fully internationalised price display, the currency symbol and locale should be configurable.
